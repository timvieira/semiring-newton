Solving Weighted Grammars with Newton's Method

Nov 04, 2026 by Tim Vieira
semirings grammars parsing algorithms dynamic-programming

Draft — This article is a work in progress. Content may change.

In short. A weighted grammar's values are the least solution of a system of polynomial equations over a semiring. This post sets up the problem and then builds three solvers, following chapter 5 of my dissertation:

  • Grammars are algebraic systems: the grammar problem and the algebraic problem are the same problem, and fixpoint iteration sums derivations by height.
  • Newton's method: sums derivations by dimension, so it can sum infinitely many derivations per iteration (one bit of precision per iteration where fixpoint iteration needs exponentially many).
  • Specialized right-linear solver: solves the linear subproblems exactly with the matrix star.
  • Hybrid algorithm: splits the grammar into strongly connected components and solves each one with the best method.
  • Code: a Python implementation for commutative semirings.

Proofs, side examples, and background are tucked into collapsible blocks (▸) for readers who want more depth.

A weighted context-free grammar $\mathcal{G}$ over a semiring $\Values$ has nonterminals $\mathcal{N}$, terminals $\Sigma$, and a set of rules $X \xrightarrow{\w} Y_1 \cdots Y_K$, each of which rewrites a nonterminal $X \in \mathcal{N}$ into a sequence of symbols $Y_1 \cdots Y_K \in (\mathcal{N} \cup \Sigma)^*$ with a weight $\w \in \Values$. The grammar assigns a value $\sem{X} \in \Values$ to each nonterminal $X$: the total weight of all derivations $\deriv$ rooted at $X$,

$$ \sem{X} = \bigoplus_{\deriv \in \mathcal{D}(X)} \w(\deriv), $$

where the weight $\w(\deriv)$ of a derivation is the $\otimes$-product of the weights of the rules it uses. When the grammar is recursive, $\mathcal{D}(X)$ is infinite, and $\sem{\cdot}$ is the least solution to the system of fixpoint equations

$$ \sem{X} = \bigoplus_{(X \xrightarrow{\w} Y_1 \cdots Y_K) \in \mathcal{G}} \w \otimes \sem{Y_1} \otimes \cdots \otimes \sem{Y_K}, $$

with $\sem{a} = \semione$ for each terminal $a \in \Sigma$. Note that $\sem{X}$ ignores which strings the derivations yield: it sums the weights of all derivations, whatever their yield. This total weight (sometimes called the treesum or, for a PCFG, the partition function) is the quantity the algorithms below compute.

Grammars are algebraic systems

The fixpoint equations of a grammar are an instance of a classical object: an algebraic system of equations over a semiring (Chomsky and Schützenberger, 1963; Esparza et al., 2007; Schlund, 2016). Fix a semiring $\mathbb{S}$ and a vector of $\mathbb{S}$-valued variables $\boldsymbol{x} = (x_1, \ldots, x_n)$. A monomial is a finite product of constants from $\mathbb{S}$ and variables, such as $c \otimes x_1 \otimes x_2$; a polynomial is a finite sum of monomials; and an algebraic system is a system of equations

$$ \boldsymbol{x} = \boldsymbol{f}(\boldsymbol{x}), $$

where each component $f_i$ is a polynomial. To turn a grammar into an algebraic system, we treat the value $\sem{X}$ of each nonterminal $X$ as an unknown. (The nonterminal $X$ is a symbol; $\sem{X}$ stands for its semiring value.) The grammar problem and the algebraic problem are essentially the same problem, but we have to be careful about which semiring $\mathbb{S}$ the system lives in, because there are two natural choices. They differ in what happens to the terminals:

  • Weights only, $\mathbb{S} = \Values$. Each terminal is replaced by $\semione$, so it drops out of the monomial. The least solution is the total weight $\sem{X}$ defined above.
  • Weighted languages, $\mathbb{S} = \Series$. Here $\Series$ is the semiring of weighted languages (formal power series), i.e., functions $L : \Sigma^* \to \Values$, with $\oplus$ taken pointwise and $\otimes$ given by concatenation, $(L \otimes L')(s) = \bigoplus_{s = u\,v} L(u) \otimes L'(v)$. A rule weight $\w$ becomes the series that gives the empty string weight $\w$, and a terminal $a$ becomes the series that gives the one-symbol string $a$ weight $\semione$. The least solution $L_X$ assigns each string $s$ the total weight of the derivations of $X$ that yield $s$.
grammar system over $\Values$ (weights only) system over $\Series$ (weighted languages)
nonterminal $X$ variable $\sem{X}$ variable $L_X$
terminal $a$ $\semione$ (drops out) the series $a$ (string $a$ with weight $\semione$)
rule $X \xrightarrow{\w} Y_1 \cdots Y_K$ monomial $\w \otimes \sem{Y_1} \otimes \cdots \otimes \sem{Y_K}$ in $f_X$, where $\sem{a} = \semione$ for a terminal monomial $\w\, \hat{Y}_1 \cdots \hat{Y}_K$ in $f_X$, in order, where $\hat{Y} = L_Y$ for a nonterminal and $\hat{a} = a$ for a terminal
derivation $\deriv$ with yield $s$ the term $\w(\deriv)$ the term $\w(\deriv)\, s$
least solution $\sem{X} \in \Values$ $L_X \in \Series$

The two are related by forgetting the strings: $\sem{X} = \bigoplus_{s \in \Sigma^*} L_X(s)$, i.e., the image of $L_X$ under the homomorphism that sends every terminal to $\semione$. When $\Values$ is the boolean semiring, a weighted language is just a formal language, $L_X$ is the language generated by $X$, and the least-solution characterization is the observation of Chomsky and Schützenberger.

This distinction matters for the algorithms below. Even when $\Values$ is commutative, $\Series$ is not (concatenation does not commute: $a\,b \ne b\,a$). The algorithms in this post assume a commutative semiring, so they solve the weights-only system for $\sem{\cdot}$; they do not compute the weighted language $L_X$ (we will see a non-commutative example that the right-linear solver cannot handle).

The fixpoint equations are underspecified: they provide necessary, but not sufficient, conditions for a solution to equal the potentially infinite sum over derivations.

Example: a grammar whose equations have two solutions

Example. The following grammar encodes the Catalan series: $\sem{X} = c + c^2 + 2\,c^3 + 5\,c^4 + 14\,c^5 + 42\,c^6 + \cdots$.

$$ \begin{aligned} X &\xrightarrow{1} X\,X \\ X &\xrightarrow{c} a \end{aligned} $$

Its algebraic system is $\sem{X} = \sem{X} \otimes \sem{X} \oplus c$. Over the real semiring, the system admits two solutions: rearranging gives $\sem{X}^2 - \sem{X} + c = 0$, so $\sem{X} \in \frac{1 \pm \sqrt{1 - 4\,c}}{2}$ by the quadratic formula. Assuming $0 \le c \le \frac{1}{4}$, the smaller solution $\frac{1 - \sqrt{1 - 4\,c}}{2}$ corresponds to the sum over derivations. The larger solution $\frac{1 + \sqrt{1 - 4\,c}}{2}$ is a fixpoint, but it is not equal to the sum over derivations.

The sum over derivations is the least solution. In $\omega$-continuous semirings (where all the infinite sums we need are well-defined), Kleene's fixed-point theorem says that the least solution is the limit of the sequence $\boldsymbol{0}, \boldsymbol{f}(\boldsymbol{0}), \boldsymbol{f}(\boldsymbol{f}(\boldsymbol{0})), \ldots$. Computing that sequence is fixpoint iteration, which initializes every variable to $\semizero$ and repeatedly applies the equations above as an update until it converges. Newton's method, too, is most naturally stated on the algebraic system: it is Newton's method for solving $\boldsymbol{x} = \boldsymbol{f}(\boldsymbol{x})$, retrofitted to semirings. We stay with the grammar view below because it lets us talk about derivations directly.

Proposition. The estimate at time $t$ given by fixpoint iteration equals the total value of all derivations of height $\le t$.

Proof (sketch)

We start with every nonterminal at $\semizero$. From there, we build height $\le 1$ derivations from the rules whose right-hand sides contain only terminals. From there, each application of the update combines the values of height $\le t$ derivations by applying the rules of the grammar to derive the values of all height $\le t\!+\!1$ derivations.This is a form of dynamic programming: the estimate at time $t$ is a memo table for a version of the computation, which makes the height $t$ an argument to break cycles. $\square$

Assuming the sum is convergent, fixpoint iteration will diligently compute it (up to each height) until every height has been covered; thus, it converges in the limit to $\sem{\cdot}$. This post describes several algorithms for solving a weighted grammar's algebraic system, each of which works best under different conditions: an accelerated fixpoint iteration variant based on Newton's method for solving equations, a specialized solver for grammars with a certain linear structure, and a hybrid algorithm that breaks up a large grammar into smaller subgrammars that can be solved separately with the best applicable method. It is adapted from chapter 5 of my dissertation, specialized here from Dyna programs to grammars; the code works for any commutative semiring.

Newton's method

Our $\Newton$ method is an accelerated solver for fixpoint problems, based on Esparza et al.'s (2007) generalization of Newton's algorithm for solving fixpoint equations over a semiring. What is interesting about $\Newton$ relative to fixpoint iteration is that it can sum infinitely many derivations in a single iteration. More specifically, each iteration sums the set of derivations by increasing dimension (defined below) rather than by its height as in fixpoint iteration (see the proposition above).In our setting, we use $\Newton$ to sum over semiring-weighted derivations; thus, our presentation will differ from that of Esparza et al. (2007), which takes Newton's method as their starting point. Newton's method for solving a fixpoint equation $\boldsymbol{x} = \boldsymbol{f}(\boldsymbol{x})$ over the reals, where $\boldsymbol{x} \in \mathbb{R}^D$ and $\boldsymbol{f}: \mathbb{R}^D \to \mathbb{R}^D$, is an iterative scheme with the update rule $\boldsymbol{x}^{(t+1)} \gets \boldsymbol{x}^{(t)} + (\boldsymbol{I}-\boldsymbol{J}^{(t)})^{-1} (\boldsymbol{f}(\boldsymbol{x}^{(t)}) - \boldsymbol{x}^{(t)})$, where $\boldsymbol{J}^{(t)}$ is the Jacobian matrix of partial derivatives of $\boldsymbol{f}$ evaluated at $\boldsymbol{x}^{(t)}$. Generalizing to the semiring setting requires retrofitting Newton's method to accommodate semirings that do not have subtraction, division, or differentiation. For our purposes, such retrofitting would be a distraction; we refer the reader to any of the following works, which discuss the connection: Esparza et al. (2007), Reps et al. (2017), Luttenberger (2009). We found the presentation in Schlund (2016) the clearest.

Etessami and Yannakakis (2009) showed that fixpoint iteration could converge exponentially slower than Newton's method.

Example. Consider the following grammar based on Etessami and Yannakakis (2009, Theorem 3.2). This grammar has a single fixpoint $\sem{\mathrm{S}} = 1$.$\frac{1}{2} x^2 - x + \frac{1}{2} = 0$, which, by the quadratic formula ($a\,x^2+b\,x+c=0 \iff x=\frac{-b\pm\sqrt{b^2-4\,a\,c}}{2a}$ with $a \mapsto \frac{1}{2}$, $b \mapsto -1$, $c \mapsto \frac{1}{2}$), has solutions $\{1\}$.

$$ \begin{aligned} S &\xrightarrow{0.5} S\,S \\ S &\xrightarrow{0.5} a \end{aligned} $$

Etessami and Yannakakis show that fixpoint iteration is exponentially slower than Newton's method in this example. Specifically, fixpoint iteration requires roughly $2^k$ iterations to gain $k$ bits of precision, whereas Newton's method gains one bit of precision per iteration. The plot below shows this using the code at the end of this post: the error of fixpoint iteration after $n$ iterations is about $2/n$, whereas the error of $\Newton$ after $n$ iterations is $2^{-n}$.

Definition. The dimension $\Dim{\deriv}$ of a derivation $\deriv$ is defined inductively. Suppose $\deriv$ is rooted at a rule $X \xrightarrow{\w} Y_1 \cdots Y_K$, and let $\deriv_1, \ldots, \deriv_m$ be its subderivations for the nonterminal children (terminal children are ignored).

  • If $m = 0$: $\Dim{\deriv} \overset{\text{def}}{=} 0$.
  • If $m \ge 1$: Let $d = \max(\Dim{\deriv_1}, \ldots, \Dim{\deriv_m})$. If the argmax is unique (i.e., no ties for the max), $\Dim{\deriv} \overset{\text{def}}{=} d$. Otherwise, $\Dim{\deriv} \overset{\text{def}}{=} d+1$.

Please refer to the figure below for an illustration.This is a variant of the Horton–Strahler number of a tree. See Esparza, Luttenberger, and Schlund (2014) for a history of Strahler numbers and their connection to Newton's method.

The dimension of a derivation is always $\le$ its height, but it is often $\ll$. The set of derivations with dimension $d$ can be infinite. In contrast, the set of derivations with fixed height is finite. For example, each derivation in the geometric series grammar ($S \xrightarrow{0.5} S\,a$, $S \xrightarrow{1} b$) has dimension $0$. What is remarkable about the set of derivations with dimension $\dPP$ is that there is an efficient linear structure relating it to the sets of derivations with dimensions $\dLE$, $\dEQ$, and $\dLT$. This allows us to grow the set of derivations we have summed over much more quickly using a specialized linear solver (below).

We provide pseudocode for $\Newton$ in Algorithm 1.Our pseudocode follows Schlund (2016, Definition 3.9), which is for context-free grammars. Here, $\Chart[Y_{(i:j)}]$ is shorthand for the product $\Chart[Y_{i+1}] \otimes \cdots \otimes \Chart[Y_{j-1}]$, and $Y_{[:i)}$ and $Y_{(j:]}$ are the children before position $i$ and after position $j$. Terminals have value $\semione$ in $\Chart$ and $\NextChart$ and $\semizero$ in $\Change$. $\NextChange$ is a grammar: the base case adds rules $X \xrightarrow{\val} \varepsilon$ whose weights are constants from earlier iterations, and the recursive case adds rules $X \xrightarrow{\val} Y_k$ in which the nonterminal $Y_k$ is the single unknown, so $\NextChange$ is a linear grammar. (Collecting the constants on both sides of $Y_k$ into one weight $\val$ reorders the product; this is where we use commutativity.) The high-level picture of $\Newton$ is much like semi-naive forward chaining: $\Newton$ tracks its analogs of $\Chart$ and $\Change$, except here $\Chart$ is the set of dimension $\dLT$ derivations, and $\Change$ is the set of dimension $\dEQ$ derivations. To efficiently determine the values for all $\dPP$ derivations, $\Newton$ solves a linearized grammar.

We discuss solving the linear subproblems below. Unfortunately, not all subproblems $\NextChange$ can be solved exactly and efficiently for all semirings; important tractable special cases include commutative semirings and cases where the subproblems are either left linear or right linear. Other cases are discussed in the literature (e.g., Esparza et al., 2007; Schlund, 2016; Reps et al., 2017). We note that fixpoint iteration methods are always available for (approximately) solving $\NextChange$; however, fixpoint iteration may not converge quickly (or at all).

As noted in other work on Newton's method (e.g., Schlund, 2016), decomposing the grammar into strongly connected components can speed the algorithm up considerably. Our hybrid algorithm (below) speeds up Newton's method in this way.

We argue for the correctness of $\Newton$ in the following proposition.

Proposition. On iteration $d$ of Algorithm 1, the value of $\Chart$ is the total value of derivations of dimension $\dLT$, and the value of $\Change$ is the total value of derivations of dimension $\dEQ$.

Proof (sketch)

We first argue that the value $\NextChange$ returned by the call to $\NewtonStep$ is precisely the sum of dimension $\dPP$ derivations. The figure above illustrates how to build dimension $\dPP$ derivations inductively from the set of dimension $\dEQ$ derivations, the set of dimension $\dLE$ derivations, and the set of $\dLT$ derivations.

We argue that our scheme for creating new derivations generates derivations of dimension $\dPP$. According to the definition of dimension, to create a dimension $\ge d\!+\!1$ derivation, we need to combine at least two $\dEQ$ derivations. That is why the base case of $\NewtonStep$ combines at least two $\dEQ$ derivations; this is depicted as the rule connecting at least two adjacent $\dEQ$ derivations; this step creates a subderivation with dimension equal to ${\cPP d\!+\!1}$. Now, because all subderivations that can combine along the spine (the path up to the root of the derivations) of the new derivation have dimension $\dLE$, the new derivation has dimension $\dPP$; we see this in the recursive case of $\NewtonStep$. Thus, the dimension of the new derivation is precisely dimension $\dPP$. To ensure that the enumeration of $\dPP$ is exhaustive, the grammar $\NextChange$ includes every rule that can combine the $\dLE$ subderivations and the base case of at least two $\dEQ$ subderivations. The grammar $\NextChange$ is a compact encoding of the value of this potentially infinite set of $\dPP$ derivations. Its solution is found by calling a specialized solver (described below) for grammars with linear rules.

In $\NewtonStep$, we see that $\NextChart$ is the sum of $\Chart$ and $\Change$, and then $\NextChart$ overwrites $\Chart$. Thus, at iteration $d$, $\Chart$ is the total value of all derivations with dimension $\dLT$. $\square$

Specialized right-linear solver

This section gives an algorithm that solves the special family of right-linear grammars, such as those generated by Newton's method.All algorithms in this section for the right-linear case work equally well for the left-linear case with straightforward modifications. Unlike fixpoint iteration and Newton's algorithm, this algorithm is exact: it can sum over the infinite set of right-linear derivations in closed form. We can perform inference efficiently because the solution can be expressed in terms of finitely many regular operations. A simple example of a right-linear grammar is

$$ \begin{aligned} X &\xrightarrow{1} b \\ X &\xrightarrow{0.5} a\,X \end{aligned} $$

Although this grammar has infinitely many derivations of $X$, we can solve for the total value of $X$ using grade school algebra: $\sem{X} = 1 + 0.5 \cdot \sem{X}$, so $\sem{X} = 2$. Right-linearity can be checked syntactically: each rule has one of two possible forms (1) a right-hand side with only terminals, like the first rule, or (2) a right-hand side whose only nonterminal is its rightmost symbol, like the second rule. A grammar can often be put into a right-linear form using simple grammar transformations, but only if the semiring is commutative.

Why commutativity matters: two more examples

The example below is not (immediately) right-linear.

$$ \begin{aligned} X &\xrightarrow{1} b \\ X &\xrightarrow{1} X\,A \\ A &\xrightarrow{0.5} a \end{aligned} $$

However, if we unfold the $A$ subgoal in the second rule and exploit the commutativity of multiplication (if permitted by the grammar's semiring) to reorder the right-hand side, then we arrive at the right-linear grammar from before. (In the weights-only system, the terminal $a$ contributes $\semione$, so moving it is harmless.) Unfortunately, not all semirings are commutative; thus, permuting the right-hand side is not allowed. In particular, the weighted-language semiring $\Series$ is never commutative. The following example, solved for its language (i.e., in $\Series$ with boolean weights, the semiring of formal languages), is linear but not right-linear.The solution to this grammar is the language $L_S = \{ a^n b^n \mid n \in \mathbb{N} \}$, which is not a regular language. Thus, it cannot be expressed as a (finite) expression involving the operations $\otimes$, $\oplus$, and $\kleene{(\cdot)}$.

$$ \begin{aligned} S &\xrightarrow{\semione} a\,S\,b \\ S &\xrightarrow{\semione} \varepsilon \end{aligned} $$

Unlike the previous example, we cannot transform this grammar into a right-linear grammar because its semiring is not commutative. (Its weights-only system, $\sem{S} = \sem{S} \oplus \semione$, is easy; it is the language that is hard.) Unfortunately, the right-linear algorithm cannot solve this grammar efficiently; we would need a general linear algorithm.

Algorithm 2 leverages a general-purpose algorithm for solving right-linear recurrences, i.e., equations of the form $\boldsymbol{x} = \boldsymbol{b} \oplus \boldsymbol{A}\, \boldsymbol{x}$ where $\boldsymbol{A} \in \Values^{N \times N}$, $\boldsymbol{b} \in \Values^{N}$. The solution is found by the matrix star operation $\boldsymbol{x} = \kleene{\boldsymbol{A}}\, \boldsymbol{b}$.

Computing the matrix star

Matrices over a semiring form a semiring (Lehmann, 1977): the matrix addition and multiplication operations are a straightforward generalization of the usual ones on $\mathbb{R}$, $[\boldsymbol{A} + \boldsymbol{B}]_{ij} = \boldsymbol{A}_{ij} \oplus \boldsymbol{B}_{ij}$ and $[\boldsymbol{A}\, \boldsymbol{B}]_{ik} = \bigoplus_{j} \boldsymbol{A}_{ij} \otimes \boldsymbol{B}_{jk}$. The star operation $\kleene{\boldsymbol{A}}$ can be computed as follows. If $\boldsymbol{A}$ is $1 \times 1$, then $\kleene{[a]} = [\kleene{a}]$. Otherwise, we can decompose $\boldsymbol{A}$ into nontrivial blocks $\langle \boldsymbol{B}, \boldsymbol{C}, \boldsymbol{D}, \boldsymbol{E} \rangle$ and apply the following blockwise recursion,

$$ \kleene{\begin{bmatrix} \boldsymbol{B} & \boldsymbol{C} \\ \boldsymbol{D} & \boldsymbol{E} \end{bmatrix}} = \begin{bmatrix} \kleene{\boldsymbol{B}} + \kleene{\boldsymbol{B}}\, \boldsymbol{C}\, \kleene{\boldsymbol{\Delta}}\, \boldsymbol{D}\, \kleene{\boldsymbol{B}} & \kleene{\boldsymbol{B}}\, \boldsymbol{C}\, \kleene{\boldsymbol{\Delta}} \\ \kleene{\boldsymbol{\Delta}}\, \boldsymbol{D}\, \kleene{\boldsymbol{B}} & \kleene{\boldsymbol{\Delta}} \end{bmatrix} $$

where $\boldsymbol{\Delta} = \boldsymbol{E} + \boldsymbol{D}\, \kleene{\boldsymbol{B}}\, \boldsymbol{C}$. It is straightforward to verify that each recursive call to $\kleene{(\cdot)}$ is decreasing in size; thus, the recursive definition is well-founded. Furthermore, if the blocks are chosen to be equal in size, then the runtime is $\mathcal{O}(|N|^3)$. (The code below uses Lehmann's equivalent one-pivot-at-a-time version.)

Background: algebraic path problems

Special cases of this algorithm for specific applications are well-known, e.g.,

  • matrix inversion (Gauss–Jordan elimination)Althoen and McLaughlin (1987) provide an interesting historical overview of the Gauss–Jordan elimination algorithm.
  • all-pairs shortest path (Floyd, 1962; Warshall, 1962; Roy, 1959)
  • finite-state automaton to regular expressions conversion (Kleene, 1956)
  • transitive closure (Warshall, 1962)

These problems were unified into what is often called algebraic path problems (Lehmann, 1977; Tarjan, 1981). Unifying these problems was just the (closed) semiring abstraction at work again! A choice of semiring—with the same underlying algorithm that sums over all paths in a graph—solves all the above problems and many others.

A useful perspective on the matrix star operation is that it computes the total weight of paths in a weighted directed graph. Paths may be regarded as a restricted family of right-recursive derivations.That is the interpretation used in Algorithm 2. Similarly, Algorithm 1 uses this interpretation to sum over linearly recursive derivations. Notice, however, that Algorithm 1 requires solutions to be linearly recursive. To use the efficient right-recursive solver, we need the subgoals to be permutable (e.g., a commutative semiring). Suppose the matrix $\boldsymbol{A}$ is the weighted adjacency matrix of a graph. Then $\boldsymbol{A}_{ik}$ is the total weight of all paths of length $=\!1$. Similarly, the total weight of all paths between $i$ and $k$ of length $=\!2$ is $(\boldsymbol{A}\, \boldsymbol{A})_{ik}$. Thus, the star operation on matrices $\kleene{\boldsymbol{A}} \overset{\text{def}}{=} \bigoplus_{i=0}^\infty \boldsymbol{A}^i$ computes the total weight of paths of length $0, 1, \ldots$ and adds them up.

Algorithm 2 $\SolveLinearName$: Solve a right-linear grammar $\mathcal{G}$ by reduction to the matrix star operation

$$ \begin{aligned} &\textbf{def } \solveLinear{\mathcal{G}}: \\ &\quad N \gets \text{the nonterminals of } \mathcal{G} \\ &\quad \boldsymbol{A} \gets \semizero^{N \times N};\ \boldsymbol{b} \gets \semizero^{N} \\ &\quad \Comment{\text{Assemble the matrix } \boldsymbol{A} \text{ and vector } \boldsymbol{b} \text{ for the right-linear solver}} \\ &\quad \textbf{for } (X \xrightarrow{\w} Y_1 \cdots Y_K) \in \mathcal{G}: \\ &\quad\quad \textbf{if } Y_1 \cdots Y_K \text{ are all terminals}: \\ &\quad\quad\quad \boldsymbol{b}_{X} \mathrel{\oplus}= \w \\ &\quad\quad \textbf{elif } Y_1 \cdots Y_K = a_1 \cdots a_{K-1}\, Y \text{ where } a_1, \ldots, a_{K-1} \text{ are terminals}: \\ &\quad\quad\quad \boldsymbol{A}_{X, Y} \mathrel{\oplus}= \w \\ &\quad\quad \textbf{else}: \\ &\quad\quad\quad \textbf{raise } \text{Error}(\text{“grammar is not right linear”}) \\ &\quad \Comment{\text{Solve the right-linear system with the matrix star operation}} \\ &\quad \boldsymbol{s} \gets \kleene{\boldsymbol{A}}\, \boldsymbol{b} \\ &\quad \Comment{\text{Convert solution vector } \boldsymbol{s} \text{ into a chart in the obvious way}} \\ &\quad \Chart \gets \NewGrammar \\ &\quad \textbf{for } X \in N: \Chart[X] \mathrel{\oplus}= \boldsymbol{s}_X \\ &\quad \textbf{return } \Chart \end{aligned} $$

The matrix star runs in $\mathcal{O}(|N|^3)$ time and can be made to run in $\mathcal{O}(|N|^2)$ space.Sub-cubic algorithms exist when $\Values$ is a ring, e.g., Strassen (1969). Note that there is a speed–accuracy tradeoff when using the right-linear solver. Often fixpoint iteration can reach a tolerable level of accuracy faster than the exact algorithm.The convergence rate of fixpoint iteration depends on the properties of the $\boldsymbol{A}$ matrix. Hybrid algorithm

This post has provided several algorithms that each work best under different conditions. This section provides a hybrid algorithm that tries to use the best algorithms available to solve a given grammar $\mathcal{G}$. If $\mathcal{G}$ is acyclic, it can be solved efficiently in a single bottom-up pass. However, if $\mathcal{G}$ is cyclical, it is best to solve $\mathcal{G}$ by breaking it up into cyclical subgrammars $\mathcal{G}^{(1)}, \ldots, \mathcal{G}^{(M)}$ by strongly connected component (SCC) decomposition of its dependency graph (an edge $X \to Y$ for each nonterminal $Y$ on the right-hand side of a rule for $X$).SCC decomposition is a common optimization for solving cyclical equations (e.g., Goodman, 1998; Nederhof and Satta, 2008; Esparza et al., 2007; Schlund et al., 2013; Mohri, 2002; Eisner, 2023; Baharev et al., 2016; Chiang et al., 2023; Purdom, 1970). This decomposition allows each subgrammar to be solved separately, provided that the solutions to the subgrammars it depends on have been computed beforehand; this can be achieved by solving the subgrammars in a topological order. By analyzing the structure of $\mathcal{G}^{(m)}$, we can determine what the best method for solving it is likely to be. Below is our ranking:

  1. $\SolveLinearName$: Because it is exact. However, it requires a closed semiring and at least one of $\{$right-linearity, left-linearity, linearity+commutativity$\}$.
  2. $\Newton$: Because it converges more quickly than fixpoint iteration methods. However, it requires that the induced linear subproblems can be solved efficiently.
  3. Fixpoint iteration: When all else fails, the subgrammar can be solved with fixpoint iteration (e.g., the agenda-based semi-naive algorithm), as it runs under the most general conditions.

Algorithm 3 provides pseudocode for our hybrid algorithm, which solves each subgrammar in a topological order where the solutions to earlier subgrammars are taken as inputs to later subgrammars. It makes use of a subroutine $\BestSolve$ that uses the ranking of solvers above to select the best strategy for solving the given subgrammar.A simple implementation of $\BestSolve$ would use exception handling to move down the list of preferred solvers. This can be sped up when the necessary properties can be checked ahead of any expensive computations. For example, linearity can be checked by looking at the rules. Note that a rule may become linear once the components it depends on are solved: in the grammar of the code example below, $\mathrm{VP} \xrightarrow{0.3} \mathrm{VP}\;\mathrm{PP}$ is linear in $\mathrm{VP}$ once $\mathrm{PP}$ is known, so $\mathrm{VP}$'s component is solved exactly by $\SolveLinearName$ even though the grammar as a whole is not linear.

Algorithm 3 $\SolveName$: Solve grammar $\mathcal{G}$ using the hybrid algorithm

$$ \begin{aligned} &\textbf{def } \SolveName(\mathcal{G}): \\ &\quad \Chart \gets \NewGrammar \\ &\quad \textbf{for } \sigma \in \SccName(\mathcal{G}): \quad \Comment{\text{Topologically ordered list of SCCs}} \\ &\quad\quad \Comment{\text{Restrict } \mathcal{G} \text{ to the current component } \sigma} \\ &\quad\quad \mathcal{G}' \gets \NewGrammar \\ &\quad\quad \textbf{for } (X \xrightarrow{\w} Y_1 \cdots Y_K) \in \mathcal{G} \textbf{ where } X \in \sigma: \\ &\quad\quad\quad \AddRule (X \xrightarrow{\w} Y_1 \cdots Y_K) \textbf{ to } \mathcal{G}' \\ &\quad\quad \Comment{\text{Solve the subgrammar with the best applicable method,}} \\ &\quad\quad \phantom{\triangleright}\ \color{grey}{\text{taking the solutions to earlier subgrammars as input through } \Chart} \\ &\quad\quad \Chart \gets \BestSolve(\mathcal{G}' \oplus \Chart) \\ &\quad \textbf{return } \Chart \end{aligned} $$

Discussion.

  • When solving an SCC with either $\Newton$ or a fixpoint algorithm, it may be necessary to use a numerical convergence threshold (or iteration limit). Otherwise, Algorithm 3 could run forever on a single subgrammar without making progress on the others.
  • In $\mathcal{G}' \oplus \Chart$, the solved values enter as constants (a rule $Y \xrightarrow{\Chart[Y]} \varepsilon$ for each solved nonterminal $Y$). Our implementation instead folds them into the rule weights, which reorders products and so assumes a commutative semiring, as does the rest of the code.
  • It is often best to optimize the grammar before solving it, e.g., by grammar transformations that produce a smaller, equivalent grammar that is more efficient to solve.

Code

The implementation takes a grammar from the leftcorner package, which provides a WCFG class, several semirings, and Lehmann's algorithm (cfg._lehmann). The main loop mirrors Algorithm 1:

def _newton(self):
    # initial chart is empty, except for terminals
    chart = Chart(self.R, {x: self.R.one for x in self.V})
    # initialize with dimension-0 derivations
    change = linearize(self, chart, chart, chart, init=True)
    while True:
        next_chart = chart + change.sol
        yield (chart, change, next_chart)
        change = linearize(self, chart, change.sol, next_chart)
        chart = next_chart

The linearization builds the matrix $\boldsymbol{A}$ and vector $\boldsymbol{b}$. The line A[r.head, ys[k]] += ... is where commutativity is used: the constant to the right of the unknown is folded into its coefficient.

Show linearize 
def linearize(self, chart, change, next_chart, init=False):
    # Matrix and vector for linearized grammar
    A = Chart(self.R)
    b = Chart(self.R)

    # recursive cases
    for r in self:
        ys = r.body
        for k in range(len(ys)):
            if self.is_terminal(ys[k]): continue
            A[r.head, ys[k]] += (
                r.w
                * next_chart.product(ys[:k])
                * next_chart.product(ys[k+1:])
            )

    # base cases for initialization
    if init:
        for r in self:
            if all(map(self.is_terminal, r.body)):
                b[r.head] += r.w

    # base cases for iterates
    else:
        for r in self:
            ys = r.body
            for i,j in combinations(range(len(ys)), 2):
                b[r.head] += (
                    r.w *
                    next_chart.product(ys[:i]) *
                    change[ys[i]] *
                    chart.product(ys[i+1:j]) *
                    change[ys[j]] *
                    chart.product(ys[j+1:])
                )

    return Change(self, A, b)

In the code, chart, change, and next_chart are $\Chart$, $\Change$, and $\NextChart$, and Change holds the linearized grammar whose solution is $\NextChange$. During initialization, $\NextChart$ is zero on every nonterminal, so the matrix $\boldsymbol{A}$ only picks up rules with a single nonterminal, which matches $\NewtonInit$. Change.sol computes $\kleene{\boldsymbol{A}} \boldsymbol{b}$.

Using it:

from leftcorner import CFG, Real, MaxTimes
from newton import newton

cfg = CFG.from_string("""
0.5: S → S S
0.5: S → a
""", Real)

newton(cfg)            # {'a': 1, 'S': 0.9999999999990905}  (39 iterations)
cfg.naive_bottom_up()  # fixpoint iteration: needs ~2^k iterations for k bits

The same code runs in any commutative semiring. Here is a small grammar with prepositional-phrase attachment in the max-times (Viterbi) semiring:

cfg = CFG.from_string("""
1.0: S → NP VP
0.4: NP → NP PP
0.6: NP → n
0.7: VP → v NP
0.3: VP → VP PP
1.0: PP → p NP
""", MaxTimes)

newton(cfg)   # S: 0.252, NP: 0.6, VP: 0.42, PP: 0.6  (exact after one iteration)

The hybrid algorithm (Algorithm 3) is newton/hybrid.py. On the same grammar, with a few extra rules for $\mathrm{V}$, it solves the components in topological order:

from newton import solve

cfg = CFG.from_string("""
1.0: S → NP VP
0.4: NP → NP PP
0.6: NP → n
0.7: VP → v NP
0.3: VP → VP PP
1.0: PP → p NP
0.5: VP → V
0.5: V → V v
0.5: V → v
""", Real)

trace = []
solve(cfg, trace=trace)
# [({'NP', 'PP'}, 'newton'),      NP → NP PP: nonlinear
#  ({'V'},  'solve_linear'),
#  ({'VP'}, 'solve_linear'),      VP → VP PP: linear once PP is solved
#  ({'S'},  'solve_linear')]      acyclic

In commutative idempotent semirings like max-times, Newton's method reaches the exact solution after at most $|N|$ iterations (Esparza, Kiefer, and Luttenberger, 2010).
