  1. Weighted Grammars as Algebraic Systems: the problem, and why fixpoint iteration can be slow

Background: semirings. Proofs, side examples, and background are tucked into collapsible blocks (▸) for readers who want more depth.

Recall the setup from part 1: a weighted context-free grammar $\mathcal{G}$ over a semiring $\Values$ has rules $X \xrightarrow{\w} Y_1 \cdots Y_K$ with weights $\w \in \Values$, and the value $\sem{X}$ of a nonterminal $X$ is the total weight of its derivations, which is the least solution of the fixpoint equations

$$ \sem{X} = \bigoplus_{(X \xrightarrow{\w} Y_1 \cdots Y_K) \in \mathcal{G}} \w \otimes \sem{Y_1} \otimes \cdots \otimes \sem{Y_K}, $$

with $\sem{a} = \semione$ for each terminal $a$. As in the rest of the series, the semiring product ⊗ is drawn as $\circ$, semiring values are magenta, and we assume a commutative semiring.

Right-linear grammars

This section gives an algorithm that solves the special family of right-linear grammars, such as those generated by Newton's method in part 3.All algorithms in this section for the right-linear case work equally well for the left-linear case with straightforward modifications. Unlike fixpoint iteration and Newton's algorithm, this algorithm is exact: it can sum over the infinite set of right-linear derivations in closed form. We can perform inference efficiently because the solution can be expressed in terms of finitely many regular operations. A simple example of a right-linear grammar is

$$ \begin{aligned} X &\xrightarrow{1} b \\ X &\xrightarrow{0.5} a\,X \end{aligned} $$

Although this grammar has infinitely many derivations of $X$, we can solve for the total value of $X$ using grade school algebra: $\sem{X} = 1 + 0.5 \cdot \sem{X}$, so $\sem{X} = 2$. Right-linearity can be checked syntactically: each rule has one of two possible forms (1) a right-hand side with only terminals, like the first rule, or (2) a right-hand side whose only nonterminal is its rightmost symbol, like the second rule. A grammar can often be put into a right-linear form using simple grammar transformations, but only if the semiring is commutative.

Why commutativity matters: two more examples

The example below is not (immediately) right-linear.

$$ \begin{aligned} X &\xrightarrow{1} b \\ X &\xrightarrow{1} X\,A \\ A &\xrightarrow{0.5} a \end{aligned} $$

However, if we unfold the $A$ subgoal in the second rule and exploit the commutativity of multiplication (if permitted by the grammar's semiring) to reorder the right-hand side, then we arrive at the right-linear grammar from before. (In the weights-only system, the terminal $a$ contributes $\semione$, so moving it is harmless.) Unfortunately, not all semirings are commutative; thus, permuting the right-hand side is not allowed. In particular, the weighted-language semiring $\Series$ is never commutative. The following example, solved for its language (i.e., in $\Series$ with boolean weights, the semiring of formal languages), is linear but not right-linear.The solution to this grammar is the language $L_S = \{ a^n b^n \mid n \in \mathbb{N} \}$, which is not a regular language. Thus, it cannot be expressed as a (finite) expression involving the operations $\otimes$, $\oplus$, and $\kleene{(\cdot)}$.

$$ \begin{aligned} S &\xrightarrow{\semione} a\,S\,b \\ S &\xrightarrow{\semione} \varepsilon \end{aligned} $$

Unlike the previous example, we cannot transform this grammar into a right-linear grammar because its semiring is not commutative. (Its weights-only system, $\sem{S} = \sem{S} \oplus \semione$, is easy; it is the language that is hard.) Unfortunately, the right-linear algorithm cannot solve this grammar efficiently; we would need a general linear algorithm.

Algorithm 1 leverages a general-purpose algorithm for solving right-linear recurrences, i.e., equations of the form $\boldsymbol{x} = \boldsymbol{b} \oplus \boldsymbol{A}\, \boldsymbol{x}$ where $\boldsymbol{A} \in \Values^{N \times N}$, $\boldsymbol{b} \in \Values^{N}$. The solution is found by the matrix star operation $\boldsymbol{x} = \kleene{\boldsymbol{A}}\, \boldsymbol{b}$.

Computing the matrix star

Matrices over a semiring form a semiring (Lehmann, 1977): the matrix addition and multiplication operations are a straightforward generalization of the usual ones on $\mathbb{R}$, $[\boldsymbol{A} + \boldsymbol{B}]_{ij} = \boldsymbol{A}_{ij} \oplus \boldsymbol{B}_{ij}$ and $[\boldsymbol{A}\, \boldsymbol{B}]_{ik} = \bigoplus_{j} \boldsymbol{A}_{ij} \otimes \boldsymbol{B}_{jk}$. The star operation $\kleene{\boldsymbol{A}}$ can be computed as follows. If $\boldsymbol{A}$ is $1 \times 1$, then $\kleene{[a]} = [\kleene{a}]$. Otherwise, we can decompose $\boldsymbol{A}$ into nontrivial blocks $\langle \boldsymbol{B}, \boldsymbol{C}, \boldsymbol{D}, \boldsymbol{E} \rangle$ and apply the following blockwise recursion,

$$ \kleene{\begin{bmatrix} \boldsymbol{B} & \boldsymbol{C} \\ \boldsymbol{D} & \boldsymbol{E} \end{bmatrix}} = \begin{bmatrix} \kleene{\boldsymbol{B}} + \kleene{\boldsymbol{B}}\, \boldsymbol{C}\, \kleene{\boldsymbol{\Delta}}\, \boldsymbol{D}\, \kleene{\boldsymbol{B}} & \kleene{\boldsymbol{B}}\, \boldsymbol{C}\, \kleene{\boldsymbol{\Delta}} \\ \kleene{\boldsymbol{\Delta}}\, \boldsymbol{D}\, \kleene{\boldsymbol{B}} & \kleene{\boldsymbol{\Delta}} \end{bmatrix} $$

where $\boldsymbol{\Delta} = \boldsymbol{E} + \boldsymbol{D}\, \kleene{\boldsymbol{B}}\, \boldsymbol{C}$. It is straightforward to verify that each recursive call to $\kleene{(\cdot)}$ is decreasing in size; thus, the recursive definition is well-founded. Furthermore, if the blocks are chosen to be equal in size, then the runtime is $\mathcal{O}(|N|^3)$. (The code below uses Lehmann's equivalent one-pivot-at-a-time version.) See also the semirings post.

Background: algebraic path problems

Special cases of this algorithm for specific applications are well-known, e.g.,

  • matrix inversion (Gauss–Jordan elimination)Althoen and McLaughlin (1987) provide an interesting historical overview of the Gauss–Jordan elimination algorithm.
  • all-pairs shortest path (Floyd, 1962; Warshall, 1962; Roy, 1959)
  • finite-state automaton to regular expressions conversion (Kleene, 1956)
  • transitive closure (Warshall, 1962)

These problems were unified into what is often called algebraic path problems (Lehmann, 1977; Tarjan, 1981). Unifying these problems was just the (closed) semiring abstraction at work again! A choice of semiring—with the same underlying algorithm that sums over all paths in a graph—solves all the above problems and many others.

A useful perspective on the matrix star operation is that it computes the total weight of paths in a weighted directed graph. Paths may be regarded as a restricted family of right-recursive derivations.That is the interpretation used in Algorithm 1. Similarly, Newton's method (part 3) uses this interpretation to sum over linearly recursive derivations. Notice, however, that Newton's method requires solutions to be linearly recursive. To use the efficient right-recursive solver, we need the subgoals to be permutable (e.g., a commutative semiring). Suppose the matrix $\boldsymbol{A}$ is the weighted adjacency matrix of a graph. Then $\boldsymbol{A}_{ik}$ is the total weight of all paths of length $=\!1$. Similarly, the total weight of all paths between $i$ and $k$ of length $=\!2$ is $(\boldsymbol{A}\, \boldsymbol{A})_{ik}$. Thus, the star operation on matrices $\kleene{\boldsymbol{A}} \overset{\text{def}}{=} \bigoplus_{i=0}^\infty \boldsymbol{A}^i$ computes the total weight of paths of length $0, 1, \ldots$ and adds them up.

Algorithm 1 $\SolveLinearName$: Solve a right-linear grammar $\mathcal{G}$ by reduction to the matrix star operation

$$ \begin{aligned} &\textbf{def } \solveLinear{\mathcal{G}}: \\ &\quad N \gets \text{the nonterminals of } \mathcal{G} \\ &\quad \boldsymbol{A} \gets \semizero^{N \times N};\ \boldsymbol{b} \gets \semizero^{N} \\ &\quad \Comment{\text{Assemble the matrix } \boldsymbol{A} \text{ and vector } \boldsymbol{b} \text{ for the right-linear solver}} \\ &\quad \textbf{for } (X \xrightarrow{\w} Y_1 \cdots Y_K) \in \mathcal{G}: \\ &\quad\quad \textbf{if } Y_1 \cdots Y_K \text{ are all terminals}: \\ &\quad\quad\quad \boldsymbol{b}_{X} \mathrel{\oplus}= \w \\ &\quad\quad \textbf{elif } Y_1 \cdots Y_K = a_1 \cdots a_{K-1}\, Y \text{ where } a_1, \ldots, a_{K-1} \text{ are terminals}: \\ &\quad\quad\quad \boldsymbol{A}_{X, Y} \mathrel{\oplus}= \w \\ &\quad\quad \textbf{else}: \\ &\quad\quad\quad \textbf{raise } \text{Error}(\text{“grammar is not right linear”}) \\ &\quad \Comment{\text{Solve the right-linear system with the matrix star operation}} \\ &\quad \boldsymbol{s} \gets \kleene{\boldsymbol{A}}\, \boldsymbol{b} \\ &\quad \Comment{\text{Convert solution vector } \boldsymbol{s} \text{ into a chart in the obvious way}} \\ &\quad \Chart \gets \NewGrammar \\ &\quad \textbf{for } X \in N: \Chart[X] \mathrel{\oplus}= \boldsymbol{s}_X \\ &\quad \textbf{return } \Chart \end{aligned} $$

The matrix star runs in $\mathcal{O}(|N|^3)$ time and can be made to run in $\mathcal{O}(|N|^2)$ space.Sub-cubic algorithms exist when $\Values$ is a ring, e.g., Strassen (1969). The runtime can be improved by decomposition into strongly connected components.The SCC-based algorithms for transitive closure date back to Purdom (1970). Note that there is a speed–accuracy tradeoff when using the right-linear solver. Often fixpoint iteration can reach a tolerable level of accuracy faster than the exact algorithm.The convergence rate of fixpoint iteration depends on the properties of the $\boldsymbol{A}$ matrix. In the case of the real semiring, we can bound the number of iterations to reach a given error tolerance in terms of the spectral radius of $\boldsymbol{A}$.

Code

$\SolveLinearName$ is solve_linear in newton/hybrid.py. It takes a linear grammar (every right-hand side has at most one symbol, after terminals have been folded into the weights, which uses commutativity), assembles $\boldsymbol{A}$ and $\boldsymbol{b}$, and computes $\kleene{\boldsymbol{A}}\, \boldsymbol{b}$ with Lehmann's algorithm (cfg._lehmann, from the leftcorner package):

def solve_linear(sub):
    """
    Solve a (right-)linear grammar, x = b ⊕ A x, by the matrix star:
    x = A⋆ b, computed with Lehmann's algorithm.
    """
    R = sub.R
    A, b = R.chart(), R.chart()
    for r in sub:
        if len(r.body) == 0:
            b[r.head] += r.w
        else:
            [Y] = r.body
            A[r.head, Y] += r.w
    N = sorted(sub.N)
    K = sub._lehmann(N, A)
    sol = Chart(R)
    for X in N:
        for Y in N:
            sol[X] += K[X, Y] * b[Y]
    return sol
